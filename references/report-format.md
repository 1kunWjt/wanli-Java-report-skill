# 实验报告格式说明

对照《面向对象程序设计》实验报告（模板）整理，生成脚本与撰写正文都以本文为准。

## 封面字段（必须保留方框与下划线排版）

对照模板截图，开头版式固定为：

```text
        浙江万里学院实验报告          （黑体大标题，居中）

                    ┌──────────────┐
课程名称：________  │ 成绩：______  │
      　　{课程名称}____ │ 教师：______  │
实验名称：{实验名称}____ └──────────────┘
专业班级：{班级}姓名：{姓名}学号：{学号}实验日期：{日期}

┌─────────────────────────────────────┐
│ 一、实验目的：                        │
│ ……（正文全部装进这个大边框）          │
└─────────────────────────────────────┘
```

排版硬性要求：

1. **大标题**：黑体，约 24–26pt，居中；标题与信息栏之间空一行。
2. **右侧成绩/教师方框**：细实线矩形，内含两行 `成绩：________` / `教师：________`；与左侧「课程名称 / 实验名称」两行并排且高度大致对齐。
3. **下划线**：课程名称、实验名称用**单行**填空下划线（短下划线，禁止折行出孤儿线）；班级行里姓名/学号/日期等**填入值**带下划线。
4. **正文大边框**：从「一、实验目的」一直到「五、实验总结」整体套一个细实线矩形框。
5. 班级行四个字段连排，字段之间用全角空格分隔：`专业班级：xxx　姓名：xxx　学号：xxx　实验日期：xxx`。
6. 页面：A4。课程/实验名称列与成绩方框列用固定列宽，填空场用窄下划线 `_`，总长度控制在左栏单行内。

## 正文结构

### 一、实验目的

直接使用老师实验要求里的「实验目的」条目，保持 `1.` `2.` 编号。

### 二、实验内容

老师实验要求里的「实验内容」。若题目很长，可保留完整题干（推荐，方便对照），或做清晰列表。

### 三、实验步骤

**必须覆盖所有题目**。每题一小段，用 `实验1：` `实验2：` … 分段。

写作标准：像人做题时的思路。

参考（模板风格偏技术叙述，我们再口语化一点）：

> 实验1：通过运行时参数 args[0] 带入一个整数形式的字符串，然后通过 Integer.parseInt() 方法将这个字符串变为整数，再通过该数除以 2 取余数，判断余数是否为 0 来判断是奇数还是偶数。

更像人类思路的写法：

> 实验1：先把命令行传来的字符串转成数字，不然没法做除法。判断奇偶就是看除以 2 余不余数，用 % 最直接。最后按余数打印「奇数」或「偶数」。

### 四、实验结果

每题固定三块：

```text
实验N：{题干原文}
1）源代码
{完整 Java 源码}
2）运行结果（截图）
{截图} 或 （请在此插入运行结果截图）
```

说明：

- 题干原文保持老师表述，不要改写丢信息。
- 源代码要完整可运行（含 class 与 main）。
- **不要**写「运行示例：java …」。
- 截图：标签栏 **1:1 粘贴** `assets/tab-chrome.png`。正文按真图（java 帮助截图 1479×574）：无横幅时从 `提示符+命令` 起，输出后**空提示符+块光标**收尾；行距 23px、首行 y≈87、右侧细滚动条；`#0C0C0C` / `#CCCCCC` 水平基线。会真实编译运行 Java。

### 五、实验总结

学生口吻复盘，150～300 字：做了什么、哪里容易错、学到什么。

## 成绩栏（紧跟封面信息，在「一、实验目的」之前）

```text
成绩：                教师：
```


`screenshots` 为本地图片路径数组（png/jpg）。空数组时**自动合成 Win11 深色终端运行截图**（真实运行 Java）；`run_hint` 显示在合成图的提示符上。

`screenshots` 为本地图片路径数组（png/jpg）。空数组则输出占位句。

## 字体

| 元素 | 字体 | 字号 |
|------|------|------|
| 大标题 | 黑体 | 24pt |
| 一级标题（一、二、…） | 黑体 | 14pt |
| 正文 | 宋体 | 12pt |
| 源代码 | Consolas / 宋体 | 10.5pt |
